# Mamaearth Returns & Growth Intelligence Pipeline

**Capstone project:** Data Analytics with AI & GenAI — E&ICT Academy, IIT Roorkee

This project builds an end-to-end returns and revenue analysis pipeline for Mamaearth order data. It combines SQL reporting, Python data cleaning and exploratory data analysis, visualizations, and a Gemini-powered Situation–Complication–Resolution (SCR) narrative with a deterministic offline fallback.

## Requirements

- Python 3.9 or newer
- SQLite 3 command-line tool
- Python packages: `pandas`, `matplotlib`
- Optional for online narrative generation: `google-genai`

Install the Python dependencies from the project root:

```powershell
python -m pip install pandas matplotlib google-genai
```

`google-genai` is only required for the Gemini API path. The narrator also supports an offline fallback.

## 1. Set up the SQLite database

Run these commands from the project root. The commands below work in Windows PowerShell when the SQLite CLI (`sqlite3`) is installed and available on `PATH`:

```powershell
sqlite3 mamaearth.db ".read sql/schema.sql"
sqlite3 mamaearth.db ".read sql/seed_data.sql"
sqlite3 mamaearth.db ".read sql/reports.sql"
```

Run the schema and seed scripts against a fresh database. **Do not rerun the seed script on an already populated database** unless you have intentionally reset the database; doing so may insert duplicate rows if the seed script is not idempotent.

The SQL reports cover customer/order summaries, revenue, product/category performance, payment methods, returns, and customers with no orders.

## 2. Run data cleaning and exploratory analysis

From the project root:

```powershell
python analysis/clean_and_eda.py
```

This step cleans the raw order data, handles duplicate records and missing values, performs the EDA calculations, and writes the derived findings to `narrator/findings.json`.

Then generate the charts:

```powershell
python analysis/visualize.py
```

The visualizations are saved under `visualizations/`.

## 3. Generate the SCR narrative

The narrator uses the findings in `narrator/findings.json` to create a Situation–Complication–Resolution summary. It supports both an online Gemini API path and an offline fallback.

### Option A — Gemini API (online)

Create a Gemini API key in Google AI Studio. Do not commit the key to source control or paste it into project files. In Windows PowerShell, set it for the current terminal session and run the narrator:

```powershell
$env:GEMINI_API_KEY="YOUR_API_KEY"
python narrator/generate_narrative.py
```

Replace `YOUR_API_KEY` with your actual key. The environment variable applies only to the current PowerShell session unless you configure it separately in Windows.

### Option B — Offline fallback (no API key)

In PowerShell, remove the key from the current session and run the narrator:

```powershell
Remove-Item Env:GEMINI_API_KEY -ErrorAction SilentlyContinue
python narrator/generate_narrative.py
```

The offline fallback generates a deterministic narrative from the computed findings and does not require an API key or network access.

### Saved sample and numeric checks

The generated narrative is written to `narrator/sample_output.txt`. The script also checks that key numeric findings are represented in the saved narrative. Confirm that all expected checks pass after running it.

For the capstone's online-integration evidence, run the script with `GEMINI_API_KEY` set and verify that the saved sample is the actual response from the successful Gemini run. If you subsequently run the offline fallback, it can replace the sample file; rerun the online path if you need to restore the online sample before submission.

## Suggested execution order

1. Create and seed the SQLite database, then run the SQL reports.
2. Run `analysis/clean_and_eda.py`.
3. Run `analysis/visualize.py`.
4. Run `narrator/generate_narrative.py` with a Gemini API key to validate the online path and save its actual response.
5. Optionally remove the API key and run the narrator again to verify the offline fallback.
6. Review `narrator/findings.json`, `narrator/sample_output.txt`, and the generated charts before submission.

## Security and reproducibility

- Never hard-code or commit API keys. Use the `GEMINI_API_KEY` environment variable.
- Do not commit virtual environments, cache folders, or other local-only files.
- Keep the source data, SQL scripts, Python scripts, generated findings, charts, and the required narrative sample in the submitted project.
- Run commands from the repository root so relative paths resolve correctly.
